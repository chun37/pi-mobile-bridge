# 同じPCに複数のアドレスを登録する

## 利用者の指定

同じPCに自宅LANの `192.168.1.100` とTailscaleの `100.64.0.10` を登録する。
利用者はTailscaleを切っている場合もあるため、LANを優先するよう指定した。
実機のAPK更新と画面操作は、今回の改修の範囲で利用者から許可されている。
24時間の端末占有や監視の再開は、この許可に含めない。

## 自動接続と手動指定

初期値は「自動（LAN優先）」である。
登録済みアドレスをLAN、その他、Tailscaleの順に試し、接続できなければ次の候補へ進む。
このため、自宅でLANが使える場合はTailscaleへ接続する必要がない。
外出先でLANへ接続できない場合は、Tailscaleのアドレスを試す。
Tailscaleアプリの接続操作は自動化しない。

1. 設定で1台のPCにLANとTailscaleのアドレスを追加する。
2. 「LANを優先して自動接続」を有効にして保存する。
3. 特定のIPを使いたい場合だけ、画面上部のメニューでLANまたはTailscaleを選ぶ。

手動指定では、選んだアドレス以外へのフォールバックは行わない。
「自動（LAN優先）」を選び直すと自動接続へ戻る。
接続中の表示には、現在試している、または接続したIPを表示する。
SSHを張り直す間は送信できない。

複数アドレスの自動モードでは、各候補へのTCP接続の待ち時間を3秒としている。
SSH認証やRPC応答の待ち時間は別である。
すべての候補が失敗した場合は、1秒から最大60秒へ待ち時間を延ばして再接続する。
再接続ではLANから試し直す。
LANアドレスがVPNのサブネット経由でも到達できる場合は、そのIPで接続することがある。
「LAN」はアドレスの分類であり、物理的な通信回線を保証する表示ではない。

## 鍵と会話の保持

PCのprofileId、SSHユーザー、ポート、ホスト鍵を共有する。
IPを切り替えても同じprofileIdの会話キャッシュを使い、開いていたセッションを保持する。
旧版の単一host設定は読み込める。
自動接続設定がない旧データは、LAN優先を初期値として扱う。
APKは上書きインストールし、端末内のSSH秘密鍵とRoomデータを消さない。

追加IPが異なるホスト鍵を返した場合は、その接続を拒否する。
ホスト鍵の不一致や初回の鍵確認を、単なる接続失敗として他候補へ迂回しない。
登録済みの鍵を自動で破棄したり、別の鍵へ固定し直したりしない。

## UIの変更

セッション一覧には検索と「デフォルト／最近使った順」の切り替えがある。
初期実装の「チャットのみ」ボタンは2026年11月20日の追加要件で削除した。
一覧対象はチャット可能なセッションのままにし、最近使った順ではワークスペースでグループ化しない。
会話ではユーザー入力とアシスタントの応答を分け、モデル名をヘッダーにまとめた。
会話を開いた際は最新のメッセージを表示し、過去の履歴を読んでいる間は常に末尾へ戻す動作にしない。
steer、followUp、中断は実行中だけ表示する。
通常の入力欄は画像添付と送信に絞り、ツールの詳細は折りたたむ。

設定画面はPC一覧と編集フォームを分離した。
公開鍵と生体認証はセキュリティ欄にまとめた。

## 実機での結果

v0.2.0をNX789Jへ上書きインストールした。
最終APKで次の試験が成功した。

| 対象 | 結果 | 証拠 |
|---|---|---|
| 複数アドレス、自動切り替え、会話保持、最新位置、送信欄 | 3件成功 | `evidence/ui-v2-delivery-device.log` |
| 既存のUI、通知、再接続、画像選択、多重購読、会話のライフサイクル | 7件成功 | 同上 |
| 鍵の暗号化保存、ホスト鍵、forced commandとPTY拒否、LANとTailscaleへの直接接続 | 4件成功 | `evidence/ui-v2-delivery-security-routes.log` |
| LTEでLAN優先からTailscaleへ切り替え、実Pi TUIとの会話 | 1件成功 | `evidence/ui-v2-cellular-final.log` |
| PC上のAndroid単体試験 | 22件成功 | `android/app/build/test-results/testDebugUnitTest/` |

自動フォールバックのUI試験では、端末自身の未待受SSHポートをLAN不可の代用として使った。
この設定はメモリ上だけで使用し、保存済みPCのアドレスは変更していない。
別にLTE実機試験を行い、試験前後にVPNのunderlayがCELLULARであることを確認した。
LTE試験では、実際に `100.64.0.10` へ自動接続し、試験専用Piとの応答を受信した。
試験後はWi-Fiを元に戻した。

途中のTailscale接続ではTCPのECONNREFUSEDを観測した。
Tailscaleアプリの表示後にLANとTailscaleの直接接続が成功したが、拒否の根本原因は確定していない。
VPNの接続表示やICMPの応答だけでは、SSHの到達性を証明できない。

最終APKのSHA-256と長時間利用の未確認事項は `status.md` に記載している。
短時間の実機試験を、設計の「外出先で1日使う」という受入条件の達成とは扱わない。
