# 実行状態の更新

## UIが参照する状態

実行状態は、PiのイベントをReducerへ渡し、`StateFlow<BridgeState>`の`SessionUiState`へ集約する。
Composeの状態表示、送信方式の選択、中断ボタン、コマンドの実行可否、通知は、この状態を参照する。
会話キャッシュとherdrの表示状態をORで結合して実行中と判定しない。

```text
Pi SDK → execution付きイベント → relay → Reducer → StateFlow → Compose
```

`working`は実行中、`blocked`は拡張の確認画面への応答待ち、`done`は実行完了、`aborted`は中断済み、`error`は失敗、`idle`は待機、`unknown`は状態不明を表す。
`agent_end`では実行完了にしない。
自動継続や再試行が終わった`agent_settled`を使い、`aborted`フラグと最後のassistantの`stopReason`から結果を区別する。

拡張の確認画面は実行状態とは別に深さを数える。
実行中でないときに確認画面を開き、閉じただけで実行中へ変わることはない。
確認画面の背後で実行が始まったり終了したりした場合も、確認画面が閉じるまで応答待ちを維持し、閉じた後に実行状態を反映する。

## 順序と世代の照合

Pi拡張0.3.0は`info`と`history`に`execution: {state, seq}`を含める。
`history`は同じ呼び出し内で履歴、ウォーターマーク、identity、実行状態を取得する。
各イベントにも発行時点の`sessionId`、`instanceId`、`execution`を含める。
relayの前回のdiscoveryが古くても、イベントの発行元を取り違えない。

Androidは同じidentity内では古いseqを実行状態へ反映しない。
別のidentityへ移った場合はウォーターマークを分け、reload後の小さいseqを受け入れる。
直前までのidentityは最大32世代保持し、その世代の遅延イベントやスナップショットで現在の状態を上書きしない。
状態を一時的に観測できなくなったことを、新しい完了通知の根拠にはしない。
一覧へ戻る操作は購読終了であり、Piやbridgeの切断ではない。
この操作では最後に確認した状態と接続可能性を保持する。
新拡張ではSDKの状態を優先し続け、旧拡張では購読終了後にherdrの更新へ戻す。
購読終了直前の遅延イベントが届いても、旧拡張の状態が固定されないようにする。

ただし実行状態のウォーターマークと会話データのウォーターマークは別である。
discoveryが実行完了を先に取得しても、遅れて到着したメッセージは会話のseqで判定して取り込む。
欠番や会話の世代変更があれば、表示状態を先に更新してから履歴を再取得する。
再取得は選択中の会話だけを対象とし、同時に1要求、処理中の追加要求は1回分へ集約する。
古い一覧取得要求の処理中に届いた`sessions.changed`を、遅い一覧応答で上書きしない。
状態を変更する一覧取得と会話取得の反映はMain dispatcherへ揃える。

## キャッシュと互換性

`Conversation`には実行状態を保存しない。
旧キャッシュの`state`キーは読み飛ばす。
Roomのスキーマ変更、DBの削除、SSH鍵の作り直しは不要である。
会話のidentityは保存し、reloadを挟んだ差分取得でも同じ会話の履歴を保持する。
遅い履歴応答で新しいメッセージ、leaf、ウォーターマークを巻き戻さない。
切断中はキャッシュの実行状態から中断操作を有効にしない。

旧拡張ではherdrの状態を初期値に使い、取得済みのPiイベントを優先する。
ただし旧拡張には原子的な実行状態スナップショットがなく、同じ順序保証はできない。
既存のPiで0.3.0の状態通知を有効にするには、本人が処理終了後に一度`/reload`する。
ユーザーの会話へ更新試験やreloadを自動送信しない。

reloadのリソース一覧や完了表示を取得する機能は今回の対象外であり、取得方法を追加していない。
実行状態を更新するために、端末へ入力する文字列を監視したり、TUIの表示文字列を解析したりしない。

## 試験

`SessionUiReducerTest`は実行状態、確認画面、snapshotによる補正、順序逆転、重複、reload、別会話、旧拡張、不正な値を試験する。
100通りの順序入れ替えでも、完了表示と中断操作が同時に有効にならないことを検証する。
`SessionPacketReducerTest`は実行状態が会話より先行した場合、欠番、世代変更、閉じたペインの遅延イベントを試験する。
`ReducerTest`は旧キャッシュ、同一会話の世代変更、遅い履歴応答と永続entryIdへの置換を試験する。

`SessionStateUiTest`は実際の状態表示と操作欄をComposeで描画する。
`SessionStateDeviceTest`は明示した専用のローカルモデルだけで、確認画面、送信、中断、完了、再取得、SSH再接続、nativeのreloadによる世代交代を試験する。
通常のユーザー会話には試験プロンプトを送らない。
試験の実行方法は`device-tests.md`を参照する。
